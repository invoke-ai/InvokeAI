The **Upscale** panel enlarges an image. An upscaler model, run through Spandrel (such as a Real-ESRGAN variant), enlarges it first. In **Refine** mode a main model then runs a short image-to-image pass over the result to add detail that fits your prompt.

Open the panel from the left region, where it sits behind Generate in the Compose and Edit layouts and behind Video in the Video layout. To upscale a gallery image without opening it, use the image menu (see [Upscaling from the image menu](#upscaling-from-the-image-menu)).

## Refine or Model only

The **Mode** switch at the top of the panel picks how the image is upscaled.

<CardGrid>
  <Card title="Refine" icon="star">
    The upscaler, then a detail pass with a main model and your prompt. Adds new detail; needs a main model of a supported family. The default, also for projects saved before the switch existed.
  </Card>
  <Card title="Model only" icon="rocket">
    The upscaler alone: no main model, prompt or detail pass. Faster and faithful to the source. Always queues once whatever **Iterations** says, because the upscaler gives the same image every time.
  </Card>
</CardGrid>

Switching modes keeps your Refine settings, so switching back restores them. Model only does not need the model capability list Refine loads, so it works while that list is loading or could not be loaded.

## What each model family needs

Refine works with **SD1.5**, **SDXL**, **FLUX.1**, **FLUX.2**, **Z-Image**, **Anima**, **Krea-2** and **Qwen Image** main models.

| Family | Tile ControlNet | Negative prompt | Detail pass |
| --- | --- | --- | --- |
| SD1.5, SDXL | Required | Yes | Tile by tile |
| FLUX.1, FLUX.2 | – | – | Whole image |
| Z-Image | Optional | When CFG > 1 | Whole image |
| Anima, Krea-2, Qwen Image | – | When CFG > 1 | Whole image |

Where a family has no Tile ControlNet, **Structure** is hidden. Where it ignores the negative prompt, the prompt is hidden and not recorded.

<Tabs>
  <TabItem label="SD1.5 / SDXL">
    - **Tile ControlNet**: required, a Tile or Union ControlNet of the same family, under **Advanced**. One is picked for you if installed.
    - **CFG scale**: kept as you set it. It goes back to 2 when you switch from a family that sets its own.
    - **Components**: taken from the main model. A **VAE** can replace the bundled one.
    - **Scheduler**: any of the family's.
  </TabItem>
  <TabItem label="FLUX.1">
    - **Tile ControlNet**: none.
    - **CFG scale**: used as guidance, kept as you set it. It goes back to 2 when you switch from a family that sets its own.
    - **Components**: a **T5 Encoder**, a **CLIP Embed** (CLIP-L) and a **VAE**, under **Advanced**. SDNQ pipelines bring their own.
    - **Not supported**: FLUX Fill models.
  </TabItem>
  <TabItem label="FLUX.2">
    - **Tile ControlNet**: none.
    - **CFG scale**: used as guidance, and set when you pick the model: 3.5 for FLUX.2 [dev], 1 for Klein, which ignores it. At most 20.
    - **Steps**: set when you pick the model: 4 for Klein 4B and 9B, 28 for Klein Base and [dev]. FLUX.2 runs all of **Steps** in the detail pass, so the panel's usual 30 would really run 30 times, more than seven times what Klein is distilled for.
    - **Components**: Klein needs a **Qwen3 Encoder** of its size (4B for Klein 4B, 8B for Klein 9B), [dev] a **Mistral Encoder**, and both a FLUX.2 **VAE**. A Diffusers install brings its own; for Klein, a complete SDNQ install does too.
  </TabItem>
  <TabItem label="Z-Image">
    - **Tile ControlNet**: optional, a **Z-Image ControlNet Tile**, under **Advanced**. The Union ControlNet has no tile mode and is not offered. Adding it lets **Structure** pull the result back toward the enlarged image, at the cost of a second network's memory and time; the pass has no tile seams for it to hold together.
    - **CFG scale**: set when you pick the model: 1 for Z-Image Turbo, 4 for Z-Image Base.
    - **Components**: a **Qwen3 Encoder** (4B) and a FLUX **VAE**. A Diffusers or complete SDNQ install brings its own.
  </TabItem>
  <TabItem label="Anima">
    - **Tile ControlNet**: none.
    - **CFG scale**: set when you pick the model: 4.5, or 6 for Anima-3.8B.
    - **Components**: a **Qwen3 Encoder** (0.6B) and a **VAE** (the Wan 2.1 VAE, installed as an Anima, Qwen Image or Wan VAE). Anima-3.8B also needs a **Qwen3.5 Encoder**.
  </TabItem>
  <TabItem label="Krea-2">
    - **Tile ControlNet**: none.
    - **CFG scale**: set when you pick the model: 1 for Turbo, 5.5 for Raw.
    - **Components**: a **Qwen3-VL Encoder** (4B) and a **VAE** (the Wan 2.1 VAE, installed as a Qwen Image or Anima VAE). A Diffusers install brings its own.
  </TabItem>
  <TabItem label="Qwen Image">
    - **Tile ControlNet**: none.
    - **CFG scale**: set when you pick the model: 4.
    - **Components**: a **Qwen VL Encoder** and a **VAE** (the Wan 2.1 VAE, installed as a Qwen Image or Anima VAE). A Diffusers install brings its own.
    - **Not supported**: Qwen Image Edit models. Without a reference image they would carry a blank one the size of the output through every step, for about 2.5 to 3 times the time and nothing gained.
  </TabItem>
</Tabs>

A value "set when you pick the model" is the model's default setting, which you can change in the Model Manager. Switching from FLUX.2 to another family sets **Steps** back to 30.

:::note[Output size]
FLUX.1, FLUX.2, Z-Image, Krea-2 and Qwen Image need sizes that are a multiple of 16. When the enlarged image is not, the panel shrinks it slightly to the nearest fitting size before the detail pass: 2040 px becomes 2032 px. Other families, and Model only, round down to a multiple of 8.
:::

## Creativity per family

**Creativity** sets how far down the noise schedule the detail pass starts: the higher, the noisier the start and the more the main model redraws. The panel offers only schedulers that start where Creativity puts the pass, and hides the field where only one is left.

<details>
<summary>Schedulers and steps for each family</summary>

| Family | Schedulers | Steps the pass runs |
| --- | --- | --- |
| SD1.5, SDXL | All of the family's | The part of **Steps** after the start: about half at **Balanced** |
| FLUX.1 | Euler, Heun | The part of **Steps** after the start: **Balanced** at 30 steps runs about the last 8 from 1024 px up |
| FLUX.2 | Euler only | Starts where FLUX.1 does, then spreads all of **Steps** over the rest of the pass, so 30 steps really run 30 times |
| Z-Image | Euler, Heun | Starts at FLUX.1's noise level; **Balanced** at 30 steps on a 2048 px result runs the last 7 |
| Anima | Euler, DPM++ 2M, DPM++ 2M SDE, ER-SDE | As Z-Image; the last 8 |
| Krea-2 | Euler only | As Z-Image; the last 7. Turbo and Raw both keep your **Steps**: Turbo, distilled for 8 steps, runs the end of a 30-step schedule |
| Qwen Image | Euler only | As Z-Image; the last 9 |

Z-Image, Anima, Krea-2 and Qwen Image count the start in steps rather than in noise level, so the panel translates Creativity for them: it starts on the step whose noise level is closest to where FLUX.1 would start. A preset therefore means the same on every family. These families need at least 2 steps.

LCM builds its own noise schedule, so it would treat the enlarged image as pure noise. Anima's Heun starts below Creativity's point and leaves noise in the image.

</details>

## Memory

| | SD1.5, SDXL | Other families |
| --- | --- | --- |
| Detail pass | In tiles, so the output can be much larger than the model generates in one go | Over the whole image at once: memory grows with the output size |
| **Tile size** | The detail pass's tiles: larger tiles can improve continuity but need more VRAM | Only the VAE encode and decode tiles (Anima's decode picks its own) |
| **Tile overlap** | More overlap reduces seams but costs time and memory | No effect |

Encoding and decoding the enlarged image with the VAE runs in tiles for every family. If you still run out of memory, see [Low-VRAM mode](/configuration/optimization/low-vram-mode/).

## Native scale

Each upscaler has a native scale, such as 4× for 4x-UltraSharp. In Model only mode the upscaler runs until the image is at least the **Scale** you asked for, then resizes it down to that size. The size preview shows the **Native scale** and a note on how it gets there:

| Scale | 2× upscaler | 4× upscaler |
| --- | --- | --- |
| 1.5× | Runs 2× once, then resizes to 1.5× | Runs 4× once, then resizes to 1.5× |
| 2× | Runs 2× once | Runs 4× once, then resizes to 2× |
| 4× | Runs 2× 2 times | Runs 4× once |
| 8× | Runs 2× 3 times | Runs 4× 2 times, then resizes to 8× |

When **Scale** equals the native scale the note is left out. A 1× model (a restoration model) keeps the input size, so **Scale** has no effect. In Refine mode the panel shows no native scale. FLUX.1, FLUX.2, Z-Image, Anima, Krea-2 and Qwen Image resize the upscaler's result to **Scale** before the detail pass; SD1.5 and SDXL keep the upscaler's size, so with a 1× model their result stays at the source size.

A Model only result's metadata is the source image's metadata plus the upscaler and the **Scale**, so **Recall** on it restores how the source was made.

### Upscalers with an unknown native scale

Upscalers record their native scale when they are installed. One installed with an earlier version has none until it is re-identified: Model only then shows no **Native scale** row, and a note under the Spandrel model says the native scale is unknown. To record it:

<Steps>

1. Under the Spandrel model, press **Open in Model Manager**, or open the upscaler's page there yourself.

2. Press **Re-identify model** and confirm. Invoke re-probes the file, and the page then shows the native scale. Re-identifying also resets the model's custom variant and default settings.

</Steps>

Only users who manage models can re-identify; others are asked to contact an administrator.

## Upscaling from the image menu

Right-click an image in the gallery and open **Upscale**:

- **Send to Upscale** opens the Upscale panel with the image as its source.
- **Upscale now, model only** lists each installed upscaler by name, with its native scale when it is known. Picking one of its factors queues a Model only upscale straight away, without changing the Upscale panel or the current Invoke settings.

| Upscaler's native scale | Factors offered |
| --- | --- |
| 1× (restoration) | 1× |
| 2× | 1.5×, 2× (native) |
| 3× | 1.5×, 2×, 3× (native) |
| 4× | 1.5×, 2×, 4× (native) |
| 8× | 1.5×, 2×, 8× (native) |
| Unknown | **Native scale**, which runs it once at whatever size it produces; **Other factors** is disabled with a note to re-identify it |

Each factor runs as Model only runs it at that **Scale** (see [Native scale](#native-scale)), so the result has the same size as one from the panel. For other factors, or a fractional Scale such as 2.5×, use **Send to Upscale**. When no upscaler is installed, the entry is disabled.

Results go to the gallery's auto-add board, wherever Invoke is currently set to send results. Their metadata is the source image's metadata plus the upscaler and its scale. If the source image's metadata cannot be read, nothing is queued and a notification says so.

This page describes working in the workflow editor in detail. For an introduction to workflows, a tour of the editor and a step-by-step walkthrough, see [Automating with Workflows](/users-guide/workflows/introduction/).

## Working in the editor

### Adding and connecting nodes

To add a node, press **Shift+A** or **Space** in the editor, or click **+** (**Add node**) in the editor's header. Type to search: every word you type must appear in the node's name, type, tags or category. Nodes are grouped by category, each with a short description and the node pack it comes from; nodes still in development are marked with a hammer icon (*Beta*). Click a node to add it near the middle of the view.

<Image src={nodePicker} alt="The node picker searching for &quot;compositor&quot;, showing the Image Compositor node in the Image category." width={420} />

A quicker way to add a node that is already connected: drag from a connection point and release it over empty space. The picker opens showing only the nodes that can connect to that point, and the new node is wired up for you.

To connect two nodes, drag from an output on the right of one node to an input on the left of another. Only compatible connection points accept the connection. An input takes one connection, but an output can feed as many inputs as you like. To reconnect, drag the end of a connection to another point; to disconnect, drag it away and release it over empty space, or select the connection and press **Delete**.

Right-click a node to **Copy**, **Paste**, **Duplicate**, **Collapse** or **Delete** it, and double-click its title to rename it. The chevron in a node's title bar collapses it to keep a large graph tidy: a collapsed node shows one port on each side, and its connections run from those ports. Connections between two collapsed nodes draw as one line with a count; selecting or deleting it acts on all of them. To make a new connection to or from a collapsed node, expand it first. Pasted nodes land at the pointer when the editor has focus and the pointer is over it, at the click point when you right-click empty space and choose **Paste**, and otherwise in the center of the visible view.

Right-click an unselected node and choose **Fit selection** to frame that node. To frame several nodes, select them, then right-click a selected node or the selection outline and choose **Fit selection**. Use **Fit view** in the editor toolbar to frame the whole workflow.

The picker's **Utility** group has three special nodes:

* **Notes** — a sticky note for explaining a workflow to others, or to yourself later.
* **Current Image** — shows the image being generated and the latest result, for keeping an eye on long workflows.
* **Connector** — a small dot for rerouting connections (see below).

#### Connectors

Connectors tidy up the wiring of a large graph. They pass a value straight through and are removed before the workflow runs, so they cannot change what it does. To add one, right-click empty space in the editor and choose **Add connector**, then connect to and from it. You can wire a connector's output first and its input later; it only accepts a source whose type matches what it feeds. Deleting a connector joins its incoming connection directly to everything it fed.

A node shows its state in its title bar. A red outline and title bar mean the node cannot run as it is, because a value is missing or invalid, or because its last run failed; the field at fault has a red name and a red border on its control. An amber outline and title bar mean the node's version does not match this installation's: a newer version of the node is available, the node is newer than this installation supports, or its version cannot be updated in place (the status button says which, and what to do). Beside the title, the status button shows a progress ring while the node runs (and the node glows), a check once it has finished, or a warning mark; point at it or move keyboard focus to it to see what it means, such as *Model is required. Pick a model.* or the error from a failed run. The info button beside it shows the node's type, node pack, version, description and notes. Nodes that are not yet stable carry an icon before the title (beta, prototype, internal or special) that explains itself on hover.

Each field row shows its actions when you point at it or move keyboard focus into it: edit the field's description, reset it to its default and add it to or remove it from the form. A field in the form has a blue name with a link mark, and an asterisk marks a required field. Each connection point grabs a little beyond its dot, so it is easy to start a connection.

Selecting a node highlights its own connections and dims the others; with nothing selected, every connection looks the same. With the minimap on, nodes that cannot run or that failed show red on it and the running node shows in the accent colour.

After a run, **Latest output** on an image node shows its result. A node whose type this installation does not have, usually from a node pack that is not installed, says so; select it for **Open Nodes Manager**, where you can install the pack (administrators only on a multi-user installation; others are asked to contact one).

When the workflow cannot run, hovering or clicking **Invoke** lists why. Problems with a node, such as a missing required input, name the node and input, and choosing one selects that node and zooms the editor to it.

### Where results go

Only nodes whose **Save to Gallery** box is checked, at the bottom of nodes that produce images, send their images to the Gallery. The images of other nodes are intermediate results that are used and then discarded. New nodes start with **Save to Gallery** turned off, so check it on the node that makes your final image.

An image node's **Board** field chooses where its saved images go. **Auto**, the default, uses the Gallery's destination, the board named under **Saving to** (see [Choosing where new media goes](/users-guide/gallery/introduction/#choosing-where-new-media-goes)). **None** saves to Uncategorized, and you can also pick a specific board. Images from nodes that have no Board field go to Uncategorized.

Beside it, **Use cache** lets InvokeAI reuse a node's previous result when its inputs have not changed, which speeds up repeated runs. On a multi-user installation, only administrators see this option.

### Your workflows

Each project keeps its own workflows, and one of them is **active**: the one shown in the editor and run by Invoke. Changes are saved with the project automatically. Click the workflow's name to switch: its menu lists the project's workflows in project order, the active one checked, and choosing another makes it active. Below the list, **New workflow** adds a blank workflow and makes it active, and **Workflow library…** opens the **Workflows** library on **In this project**. Its left rail lists the places to look:

* **In this project** — the project's workflows. Open one to make it active, or start a **New workflow** from the toolbar.
* **Recent** — the saved and bundled workflows you have opened, most recently opened first.
* **My library** — workflows you have saved with **Save to library…**, for use in other projects.
* **Templates** — the workflows that ship with InvokeAI, such as *Text to Image - SDXL*, *Flux Text to Image* and the video workflows. Opening one adds a copy to your project.
* **Shared with me** — public workflows on a multi-user server, your own included.

Under the places, **Tags** lists the tags used in the current place, each with how many workflows carry it. Check several to see workflows with any of them; **Clear** unchecks them all.

The toolbar above the cards is the same everywhere. Search matches names, descriptions and tags on every place. The **Sort** menu names the current order and sets both the key and its direction, such as **Newest first** or **A to Z**: **My library** and **Shared with me** sort by **Last opened**, **Last updated**, **Last run**, **Date created** or **Name**; **In this project** sorts by **Project order**, **Name**, **Last updated** or **Last run**; **Templates** always lists by name; **Recent** always lists the most recently opened first. Sorted by **Last run** or **Last opened**, workflows never run or never opened come last in either direction. **Last run** for a library template follows runs of its linked copies in your projects. The view menu beside it, its glyph showing the current layout, shows the workflows as a **Grid** of cards or as a **List**; for the grid it also switches between small and large cards and chooses whether thumbnails **Fill** their cards, cropped at the edges, or **Fit** whole. A list row shows the thumbnail, name, base model, readiness and the date of the current order (when it was last opened, run, created or updated), and a **…** menu at its end. **Open** and **Preview** appear beside it when you point at the row; the **…** menu always offers **Open**, and the detail rail **Preview**. Right-click a card or row, or use its **…** menu, for that workflow's actions without changing which workflow the detail rail shows. On **In this project**, **New workflow** sits at the end of the toolbar. The line under the toolbar counts the matching workflows and names the checked tags.

A dot beside each card's or row's facts says whether the workflow can run here: green when it is ready, amber when it needs models you have not installed, and red when it uses node types this installation does not have. The detail rail on the right lists the requirements and offers the installs, and names the missing node packs.

The detail rail describes the selected workflow before you open it: where it comes from (a template, your library, a shared workflow or this project), its author and version, how many nodes and inputs it has, **You set** (the inputs its form exposes, grouped under the form's headings) and the author's notes, cut to three lines until **Read all notes**.

**Preview**, a card's or row's **Preview** action, a press on the rail's thumbnail, or <kbd>Space</kbd> on the selected card or row shows the workflow in place of the places and the cards; the detail rail, with **Open**, the installs and its **…** menu, stays beside it. Three tabs at the start of the bar above it switch what it shows. **Nodes** draws the workflow as saved, with each node named as in the editor, even when it would not run here. It opens simplified: small value nodes such as a prompt or the steps fold into labels on the node they feed, and collect and metadata nodes are hidden; **Show all** draws every node where its author placed it. Markers show the nodes whose values you set, the ones that need a model you have not installed, and the result. Select a node, or press <kbd>Enter</kbd> on it, for a card with its note, its values and the nodes it connects to; **Find a node**, at the end of the bar while **Nodes** shows, highlights nodes by name, and <kbd>Enter</kbd> moves between the matches. A workflow too large to read at full size opens at a readable size from its start, with a minimap. **Inputs** shows the workflow's form as its author arranged it, with the saved values and the models still to install; each input links to the node it sets. **Graph** shows the graph the workflow compiles to, the JSON the server is sent when it runs, or says why it would not compile. The **…** menu at the end of the bar copies or downloads the workflow's own JSON, the file the editor imports. While previewing, the top of the detail rail counts the workflow's place in the current results, with arrows to the previous and next one (<kbd>↑</kbd> and <kbd>↓</kbd> on them step too). The back button or <kbd>Esc</kbd> returns to the cards as you left them; the next <kbd>Esc</kbd> closes the library.

When a project workflow came from a library template, its detail rail shows the linked template and its revision, and says when the template is newer than the copy. **Update from template** replaces the copy with the template's current version (Undo restores your edits), and **Update library template** writes the copy over the template.

In a narrow window the places become a menu at the start of the toolbar with a **Tags** button beside it that counts the checked tags, and the selected workflow's details open from a bar under the cards. A preview fills the window above that bar, without **Find a node**, and the arrows sit beside the workflow's name in the bar.

The library remembers the place and the **In this project** order until you leave the app, and **Nodes**, **Inputs** or **Graph** until you close it, and the other places' order, the layout, the card size and the thumbnail choice for your account. Closing it clears the search and the checked tags.

Opening a library workflow adds an independent copy to the project; the library's version is untouched. If the project already has a copy, opening the template asks what to do: **Open copy** switches to the existing copy, **Add new copy** makes another one, and **Replace copy** replaces the copy's graph with the library version while keeping its name. A replace can be undone in one step.

Changes to a project's workflows never change the library by themselves. **Save to library…**, in the editor's header, saves the workflow as a new library template with the name you give it, including its form and its current settings as defaults. Owners can update their own linked saved workflow templates, and multi-user administrators can update any user's saved non-bundled template; bundled templates remain read-only. If the template has changed since you opened it, you can save as a new template instead, or review the current one and replace it deliberately. Replacing a template also affects workflows that use it through the **Call Saved Workflow** node.

Add comma-separated tags, such as `portrait, SDXL, upscaling`, in the workflow's **Details**; they appear under **Tags** in the library. Each workflow also keeps its own undo history while the project is open.

:::note[Changed from v6]
In InvokeAI 6, editing a workflow opened from the library saved every change straight back to the library. Workflows now belong to their project and autosave there; the library changes only when you choose **Save to library…** or **Update library template**.
:::

To share a workflow, use **Export** → **Export JSON** from the **⋯** menu, or **Copy JSON** beside it; others can load it with **Import from JSON…**. If parts of a file cannot be loaded, such as nodes of an unknown kind, one notice lists everything that was skipped. An image made by a workflow also carries the workflow in its metadata: right-click the image and choose **Load Workflow**. **Download workflow as PNG** in the editor toolbar, or **Export** → **Download as PNG** in the **⋯** menu, saves a picture of the whole graph, at up to twice screen resolution, for documentation or sharing. A large graph is saved at a lower resolution, with a notice when that falls below screen resolution; one too large to stay legible as a picture is not exported, so share its JSON instead. Closing the workflow editor while the picture is being prepared cancels the export.

## Common node patterns

A few groups of nodes appear in almost every image workflow. Knowing what they do makes it easier to read the bundled workflows and to build your own.

* **Model, prompts and denoising.** A model loader, such as **Main Model - SDXL**, provides the model's parts: the UNet or transformer that denoises, the text encoders (CLIP) and the VAE. Prompt nodes turn text into *conditioning* using the text encoders. The denoise node needs both positive and negative conditioning, even if the negative prompt is empty.
* **Noise and seeds.** Text-to-image starts from random noise, made by **Create Latent Noise** from a **Seed**, **Width** and **Height**. Its **Noise Type** must match the model family: **SD** for SD 1.5 and SDXL, or the matching family for FLUX, FLUX.2, SD3, CogView4, Z-Image or Anima. Type a seed for repeatable results, or connect a **Random Integer** node to the seed for a new one on every run.
* **Images and latents.** Models work on compressed *latents*, not pixels. **Image to Latents** encodes an image with a VAE, for image-to-image; **Latents to Image** decodes the result back into pixels.
* **Scaling.** **Scale Image** and **Resize Image** resize pixels, **Scale Latents** and **Resize Latents** resize latents, and **Image-to-Image** runs an upscaling model. Latents are already compressed, so enlarging the image and then refining it often gives more detail than enlarging the latents.
* **Control and LoRAs.** A **ControlNet** node turns a control image, usually prepared by a processing node such as **Canny Edge Detection** or **Depth Anything Depth Estimation**, into a control input for the denoise node. **Apply LoRA** nodes (one per model family, such as **Apply LoRA - SDXL**) add a LoRA to the model's UNet and text encoders.
* **Iteration and batches.** **Iterate** runs the rest of the graph once for each item in a collection, and **Collect** gathers several values into a collection. For example, **Random Range** makes a list of seeds and **Iterate** feeds them one at a time to the noise node, generating one image per seed. For more complex repetition, see [Loop Nodes](/users-guide/workflows/loop-nodes/).

## Adding community nodes

The community has written many more nodes, from image effects to prompt tools. The easiest way to install a node pack is the [Custom Node Manager](/users-guide/workflows/custom-node-manager/): paste the pack's Git URL and it is downloaded and loaded without restarting. To install one by hand, clone or download it into the `nodes` folder of your InvokeAI root, then click **Reload** in the Custom Node Manager or restart InvokeAI. `git clone` is the better choice, because `git pull` then updates the pack. The [Community Nodes](/users-guide/workflows/community-nodes/) page lists available packs.

## Keyboard shortcuts

These work while the workflow editor has focus. On macOS, use **Cmd** in place of **Ctrl**.

| Shortcut | Action |
|---|---|
| **Shift+A** or **Space** | Add a node |
| **Ctrl+C** / **Ctrl+V** | Copy / paste nodes, with the connections between them |
| **Ctrl+Shift+V** | Paste nodes, keeping the connections that fed them from the rest of the graph |
| **Ctrl+D** | Duplicate the selected nodes |
| **Ctrl+A** | Select all nodes |
| **Delete** / **Backspace** | Delete the selected nodes |
| **Ctrl+Z** / **Ctrl+Shift+Z**, **Ctrl+Y** | Undo / redo |
| **Shift**-drag | Box-select nodes |
| Middle- or right-drag | Pan the view while the box select, lasso or eraser tool is active (with the pan tool, drag empty space) |
| Hold **Ctrl** while dragging | Snap to the grid |
| **Ctrl+Enter** | Invoke |

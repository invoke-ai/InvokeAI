# Verifying user flows

Paths and commands are relative to this package. This map connects user vocabulary to existing owners and reproducible checks; it is not an exhaustive feature inventory. Read the linked owner contract before choosing a scenario. The commands and required completion gates remain in [AGENTS.md](AGENTS.md#performance-and-validation).

## Start from a known state

For manual interaction and visual checks, use `pnpm dev:mock` as described in [browser verification](AGENTS.md#browser-verification). The [mock backend](scripts/mock-backend.mjs) owns reset and fault controls; [fixtures](scripts/mock-backend-fixtures.mjs) own representative and empty profiles. Reset between scenarios. Its in-memory HTTP behavior has no Socket.IO and does not establish real backend authorization, persistence, or model execution.

The production-build journeys start and stop their own preview/backend processes. Use their package commands instead of reimplementing a driver. Their setup, fault injection, and selectors are executable examples; use a spare port for focused runs and respect the single-machine performance gate.

## Choose and report evidence

- Run an owner test with `pnpm test <path>` or `pnpm test:browser <path>`. Extend the existing fixture at its owning interface for an uncovered failure; do not infer coverage from a nearby test's name.
- For a UI change, inspect the changed interaction, keyboard/focus behavior, and relevant loading/error/recovery states in the browser. Report the fixture or setup and visual evidence. Accessibility checks and screenshots each prove only part of the experience.
- Report the claim, scenario, result, environment, and material limit. For example: held-prompt recovery passed in the recorded Chromium build with real IndexedDB; process crashes and full storage were not exercised. Keep artifacts in their ignored output directories.
- For performance claims, use the [performance guide](performance/README.md). Routine resource observations do not provide timing measurements. Required release checks remain required even when a focused scenario passes.

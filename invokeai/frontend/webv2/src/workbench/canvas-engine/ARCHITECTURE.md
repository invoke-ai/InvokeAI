# Canvas Engine Architecture

Paths are relative to `src/workbench/canvas-engine/`, except those starting with `widgets/` or `canvas-operations/` (relative to `src/workbench/`) and `src/`, `scripts/`, or `vitest.*` files (relative to the webv2 package).

## Ownership invariant

Workbench reducer owns serializable canvas contract. Per-project canvas engine owns pixels, decoded images, rendering, interaction, history, transient editing state, caller-owned raster snapshots. Engine-owned objects never enter reducer actions or persisted project state. Brush, eraser, shape and text options belong to the account: `canvas-operations/toolMemory.ts` seeds a new engine's option stores from the account's preferences (normalized against the engine defaults), takes in what another engine stores later except for its own unsaved changes, and writes only the tools it changed, merged into the stored record, after half a second of quiet and on disposal, never once the account changed; so a warm engine and the one opened meanwhile never overwrite each other with stale options. Brush color stays the project's color pair. The active tool and the quick-switch bookmark belong to the engine lifetime and survive cooldown while the registry retains that engine; disposal hands them, with the number of undo steps it dropped, to the project's next engine in the session (`canvas-operations/engineRegistry.ts`), whose History pane says those steps were cleared. A project with no carry starts on Brush when its canvas is blank (no layer but empty inpaint masks) and nothing is selected, else on View, so an older project's selected empty mask is never painted by a first stroke. Quick-switch memory updates its return target only on explicit non-null selection changes outside engine edits; deselection, temporary engine selections, and removed targets do not overwrite it. The next explicit switch records the layer actually being left, including an automatic selection after an edit.

Canvas mutations are explicitly project-addressed. `CanvasProjectMutation` is the complete reducer mutation vocabulary; the only `WorkbenchAction` carrying one is:

```ts
{
  type: 'applyCanvasProjectMutation';
  projectId: string;
  mutation: CanvasProjectMutation;
  origin?: 'user' | 'system';
}
```

Reducer handles this envelope only through `updateProjectById`. No canvas action infers its target from active project.

Each engine gets a `CanvasProjectMutationPort` bound to its immutable `projectId`. Port exposes `getCanvasState()`, `subscribe()`, `dispatch(mutation, origin?)`, `commitEdit(intent)`. It neither exposes global workbench dispatcher nor follows active-project changes. Widgets use `useCanvasProjectMutationDispatch`, which captures current project ID and emits same envelope. So project switches and colliding layer IDs cannot redirect a delayed engine mutation to another project.

Port `dispatch()` returns whether named project's canvas identity changed. User-origin mutations may auto-route invocation controller; history replay, synchronization, rollback, bitmap persistence dispatch as `system`. Prepared transactions dispatch their document mutation as `system`, verify reducer and mirror postconditions, then call `commitEdit()` exactly once for a successful user edit. Paint calls `commitEdit({ kind: 'paint' })` synchronously at stroke commit, so delayed persistence upload can never steal a later manual route.

Paint persistence clears dirty result only after intended layer accepts bitmap reference. Rejected update keeps dirty pixels for retry; layer or project deletion is terminal and discards obsolete persistence work. Rule applies equally to raster/control paint sources and paint-backed masks.

## Document contract and hierarchy

`CanvasDocumentContractV3` holds four stack forests, `document.stacks.{raster, control, regional_guidance, inpaint_mask}`. Each forest: top-first tree of leaves (unchanged v2 leaf contracts) and pass-through groups (`type: 'group'` with `id`, `name`, `isEnabled`, `isLocked`, optional overlay-only `isHidden`, `children`). Node belongs to exactly one stack, ids unique across document, groups nest at most ten levels deep, document holds at most 10,000 nodes. `selectedLayerId` may name leaf or group; leaf-only tools refuse a group rather than guess a descendant. Groups carry no opacity, blend mode, transform, or raster surface: they only organise leaves and gate their effective state. Loader refuses older document versions; nothing migrates them.

`document/documentIndex.ts` builds one index per `stacks` identity (parent, path, sibling index, document order, ancestor-effective enabled/locked/hidden per node). Selection and bbox edits keep `stacks` and cost no index. Value edit (transform, opacity, blend, name, source, config, or a flag) goes through `updateNodeValues`, which finds each edited node via index and copies only sibling arrays on its path (cost: sibling counts along edited paths, never the forest), so `stacks` changes; it then registers a derived index for new forests extending previous one, and records the edit's replaced nodes (before and after; ancestors rebuilt only for a new child array are not listed) against new forests: `byId` is a layered map reading through to previous index for every untouched id, `nodes` and `leaves` materialize only when a consumer reads them (`leaves` keeps identity when no leaf object changed), and only entries constructed are edited path plus subtree under a group whose flags changed. After eight derivations chain flattens onto its plain root: one override layer holding newest entry of every id chain touched, still pointing consumers at root's cached compile so flattening recompiles only what chain changed; only when overrides cover more than a quarter of root is a plain index rebuilt. So lookups read through at most nine layers; nothing older than root is retained. `document-model/documentModel.budget.test.ts` pins this at 10,000 nodes: leaf edit revisits and constructs `depth + 1` entries, compiles `depth + 1` semantic nodes (ancestors keep counts without walking subtrees) and one leaf, answers `lookupDocumentLeaf`/`lookupDocumentNodeState` without materializing node list; complete reducer → mirror value edit does same with no forest diff.

`document-model/documentModel.ts` compiles `SemanticLeaf`s and `SemanticNode`s from that index: `contributionEnabled`, `effectiveLocked`, `documentHidden` fold in every ancestor; leaf or node keeps identity while its contract object, place, and ancestor-effective state are unchanged. Every consumer deciding visibility, contribution, editability, export, or what a panel row shows reads these (or `isLeaf*` predicates), not node's own flags; `model.refusalFor(command)` is the single eligibility authority for enabling a command before it runs; for `reparent`, `group`, `ungroup`, `remove` it runs same validator `prepare` uses without materializing an edit (`editsMaterialized` stays zero), so drag hover or toolbar render never builds an inverse or postconditions. Locks are all-or-nothing over subtrees: no command edits, moves, groups, ungroups, or inserts into a subtree that holds a locked node or sits under one, while name, enablement, and lock flips stay open so a locked node can be unlocked.

Model prepares structural edits (`insert`, `remove`, `duplicate`, `move`, `reorder`, `reparent`, `group`, `ungroup`, `patch*`, `set-*`, `translate`, `select`); `commitPrepared` commits them. Restructuring lands as one `applyCanvasLayerStackMutation`; reducer applies it as `add`, then `move`, then `removeIds`, then flag and selection updates, refusing whole mutation when any step is invalid or result exceeds limits. Insertion anchors are exact: before a surviving sibling under its current parent, after a surviving sibling, top of captured parent, nearest surviving group on captured path, then stack top. Inverses restore removed or moved nodes as maximal sibling runs anchored to their unmoved neighbours, so undo reproduces previous structure exactly.

Document mirror reports in leaf terms, in document order. For value edit it folds recorded edits since its last document (`valueEditBetween`, at most sixteen; record holds its predecessor weakly so superseded forests are never retained) and touches only those nodes: edited leaf is changed, and source-changed when its raster source or mask bitmap changed; group flag flip reports as changed the descendant leaves whose ancestor-effective state actually moved (never source-changed); group adjustment, opacity or blend edit sends its descendant leaves down non-destructive recomposite channel; group rename reports nothing. Only a structural edit, an unrecorded step or a wholesale replacement diffs forests by leaf identity and ancestor-effective state, where a reparent that changes no leaf's effective state reports an order change only. `onLayersChanged` says whether forests were restructured, so engine prunes group surfaces only then, and invalidates each changed layer once.

### Layers panel

`widgets/layers` consumes the seam and owns nothing about the document. `widgets/layers/layerTreeRows.ts` turns `compileDocumentNodes` plus per-project panel state (expansion, name filter) into `LayerTreeRow`s keyed on forests, so selection or bbox change rebuilds no row, and row keeps identity while its node, place, effective state, sibling position and expansion are unchanged; `widgets/layers/layerPanelRows.ts` flattens four stacks into one list with a header per non-empty stack. `widgets/layers/LayersTree.tsx` virtualizes that list (fixed row heights per density, focused item always mounted, each slot drawing the row its key names so a list change never relabels a mounted node) and is one WAI-ARIA tree: stack headers are level-one tree items that expand or collapse their stack, rows are tree items beneath them, every control inside an item is pointer-only (`tabIndex={-1}`) and hands focus back to its item when pressed, and whole tree is a single tab stop with roving focus that survives focused item unmounting; selection toolbar above it is likewise one tab stop with arrow keys between its buttons. Keyboard: arrows, Home/End, Left to parent or header, Right into a stack or group, Enter/Space to select (with Shift/Ctrl), Alt+arrows to reorder and reparent (carrying the selection when focused row is part of it, as a drag would), F2 to rename (rename committed by clicking elsewhere leaves focus where the click put it), Shift+F10 for row or stack menu, which carries every pointer action including hide-on-canvas. Tree holds the single drag context (pointer-within collision scoped to the stack, deterministic edge auto-scroll, hover-expand, indicator projected in linear time and checked with `model.refusalFor` so a locked, cyclic or too-deep landing shows its refusal inline), the single menu/properties host addressed by node id, and every store subscription and commit; row receives one view model and one stable command handle, and a primary that changes outside the panel is revealed once: its collapsed stack and groups open and it scrolls into view, after which panel's scroll position is its own. Above 2,000 nodes panel degrades explicitly: thumbnails and drag reordering switch off, every command stays. `widgets/layers/layersPanel.budget.test.ts` pins 2,000-node facts (exact row counts, one node visit per build, row identity across selection and a local expand, linear drop projection); `widgets/layers/LayersTree.browser.test.tsx` pins mounted-row window, per-row commit counts (`layerPanelDiagnostics`) for selection and scroll, thumbnail requests, drag validation counts, tab stop, degraded mode on a real 2,001-node document, external reveal, edge auto-scroll, keyboard journeys in Chromium; `scripts/run-accessibility-journeys.mjs` runs Axe over panel on representative project.

### Properties and Transform

Tool and operation settings live off the surface, as editor panes of Layers panel (`widgets/layers/panes`). Properties pane renders running operation first, then active tool, each as `ToolPropertyForm` / `OperationPropertyForm` (`widgets/canvas/tool-presentation`): named, collapsible groups of typed rows (optional preview card on top), with ONE sticky footer pinned to pane's bottom edge — running operation's verbs (status chip, Process/Reset, Apply with its save-as menu, Cancel), else tool form's (transform session's Apply/Cancel). Group ids are global so tools sharing a group's component keep its DOM and collapse state across the switch. Transform pane edits selected layer's transform without a tool — each field commits one undoable `patch`, and while Transform tool holds a session same fields drive its preview and Apply / Cancel land or drop it. Forms read engine's option stores and document transactions directly: no state mirror. Staging and generation lock tool groups in place (`inert`), footer honors same lock itself (it sits outside the sections), and an operation keeps its own controls live with Cancel always reachable. Panes are fixed parts of panel — `LayerEditorPanes` owns their tabs, preferred height and collapse, persisted through Layers widget's project state — not movable widgets. Same blocks host Color/Swatches workspace (project foreground/background pair), History pane (engine's labeled undo/redo stack via `history.getEntries()`/`stepBy`: a Start row stands for the canvas before the oldest kept step and notes `evicted` steps or the `dropped` ones a previous engine of the project was disposed with (the registry hands their count, evictions and cooldown trims included, to the next engine's history), both until the history is next cleared; jumps wait while `documentEditingLocked`; Clear history asks first; below the steps, the project's restore points), and Overview navigator (`previews.drawDocumentOverview` plus live viewport handle).

## Package and capability boundaries

`canvas-engine/` is rendering and editing core. May import engine-internal modules and shared canvas contracts, mutations, and project mutation port. Must not import React, widgets, application canvas operations, generation graphs, socket infrastructure, or backend networking. `canvas-engine-independence` rule in `src/architecture/dependencyPolicy.ts` enforces widget, canvas-operation, and generation boundaries through `pnpm architecture:check`; review must catch React, socket, and networking imports.

`canvas-operations/` owns application workflows such as Filter and Select Object. Coordinators may depend on queues, uploads, model selection, narrow engine capabilities. Their stores are React-free and `useSyncExternalStore`-compatible; React adapters stay under `widgets/`.

Public engine handle splits into capability groups such as `CanvasDocumentCapability`, `CanvasExportCapability`, `CanvasLayerCapability`, `CanvasLifecycleCapability`, and interaction/store capabilities. Production consumers request smallest aggregate they need. `canvas-construction-private` rule in `src/architecture/dependencyPolicy.ts` limits full `CanvasEngine` type to `canvas-operations/createCanvasEngine.ts` and `canvas-operations/engineRegistry.ts`; tests may construct full-engine fakes. Unused `fflate` dependency removed.

`CanvasCoreStores` holds interaction state only. `canvas-operations` creates and owns Filter and Select Object snapshots; application-session state cannot leak into core store contract.

Controllers talk through constructor-injected ports or public capabilities. They do not reach into another controller's private maps, and core engine never receives global workbench dispatcher.

## Controllers

`engine.ts` is core composition root and document-event router. New behavior goes in a focused controller with explicit dependencies and idempotent `dispose()`.

Current extracted ownership includes:

- `RasterController`: base layer caches, decoded bitmap leases, derived, adjusted and group surfaces, the spatial adjustment worker service, rasterization jobs, invalidation, residency pins, working-set eviction, unified raster-memory controller.
- `RasterMemoryBudgetController`: base, derived, group, decoded, detached, reserved and overage byte accounting plus generation-scoped reservations and operation-owned reservations and pins.
- `RenderController`: render targets, scheduler construction, previews, render lifecycle.
- `HistoryController`: engine-owned history, guarded async replay with failure reporting, inactive byte trimming.
- `PersistenceController`: dirty-bitmap flush barriers (whole document, or one layer through `applicationHost.flushLayerUploads`) and disposal.
- `EditingController`: selection state and exclusive edit-lease lifecycle.
- `TransformEditingController` (under `EditingController`): transform sessions, previews, parameter commits and paint bakes, plus `layers.beginTransform` and the wait of a session requested before its layer's pixels persist. It alone decides when that wait opens a session or ends; `engine.ts` routes it document changes, tool switches, Escape, replays, document replacement and final upload failures.
- `ColorSampleController`: one-shot color requests and the workbench color router, and which of them receives each pick.
- `PaintLineEndController`: where the last brush or eraser stroke ended on each layer, followed through the layer's changes (see "Input ownership and frame scheduling").
- `InteractionController`: public tool commands and their disposal boundary.
- `LayerController`: guarded layer mutations and thumbnail capability ports.
- `RasterExportController`: guarded layer rasterization, transformed copies, encoding, reservations, pin leases. A rasterization that failed because the source cannot be read reports a `LayerUnreadable` refusal (`layerExportGuards.ts`) carrying the layer's id and name, never `not-ready`: waiting cannot fix it, so every consumer (crop, merges, boolean merges, copies, conversion, extraction, duplicate, filter, Select Object, Run Workflow, snapshots for generation and PSD, composite export) refuses with it instead of asking the user to retry, and the message names the layer to disable, delete or replace. An operation reading several layers names the first that failed in its read order; crop all lists each one it skipped. Unreadable means the image resolver threw `CanvasImageMissingError` (the `ImageResolver` contract: the image is missing, or not readable by this user; the production resolver maps 403, 404 and 410 to it), the fetched image did not decode, or rendering threw. Any other resolver failure (network, server, an expired session) is wrapped as `ImageUnavailableError` and is transient: operations and readiness gates report `not-ready`, and crop all refuses the whole crop as `not-ready` instead of skipping the layer. The rasterizer remembers either failure per cache entry, keyed by cache version, document generation and source, with its kind, and a retry of the same source that fails again with the same kind raises no second error notice; a change of kind (a fetch outage that turns out to be a deleted image) is reported, with the `ImageUnavailableError` itself (naming the image, the resolver's error as its cause) for a transient one. Two questions read that record. `getFailure` (the kind recorded for the layer's current key) drives the readiness gates that never rasterize themselves (Merge Down, boolean merges, extraction): they answer unreadable for as long as an `unreadable` failure holds, and `not-ready` for an `unavailable` one. `isBackingOff` (either failure's retry backoff, 3 s doubling per repeated failure up to 60 s, is still running) drives the compositor, which skips the layer meanwhile instead of reading its image every frame; the backoff's end invalidates the layer, so a displayed layer retries on its own. A readiness gate asked about a layer also retries it in the background while it answers from the record (a layer off screen or disabled is never redrawn to do so): at once for an `unavailable` failure, so trying again after an outage ends fetches without waiting out the backoff, and only once the backoff is over for an `unreadable` one. A running job is joined, never duplicated. Explicit operations (crop, export, merges) always try again. A retry that fails again restarts the backoff without a second notice; a success or any change to the layer clears the failure. Thumbnails show `error` for both kinds.
- `PsdExportController`: immutable PSD planning, snapshot capture, reservation, execution, cancellation.
- `StagedResultController`: guarded staged-candidate acceptance and its history entry.
- `PixelEditController`, `SelectionImageController`, `LayerMutationController`: atomic pixel/document publication at their respective boundaries. Pixel editor materializes control layers and raster-image layers in place before destructive edits (brush and eraser alike), keeping conversion plus pixels in one undoable transaction.
- `CropLayerController`: crops one layer, or every leaf of every stack, to the frame; crop-all is one entry. Both paths share one eligibility rule: a leaf locked by itself or an ancestor, or with a source the export cannot bake, is never cropped. A single crop refuses such a leaf, an `unreadable` one, and one wholly outside the frame (`outside-frame`: the explicit crop would empty it). Crop all first crosses the paint-upload barrier (`flushPendingPixels`, not waiting for held pixels), so an acknowledgement replacing a just-painted leaf cannot land mid-read and refuse it as `stale`. It skips locked and unreadable leaves when their contract's content reaches past the frame, counting the locked ones (`skippedLocked`) and listing the unreadable ones in document order (`skippedUnreadable`), so the result can say what was left alone, by name, even when nothing was cropped, and one leaf that cannot be read never blocks the rest; a leaf already inside the frame, empty or unsupported is left alone; a leaf wholly outside is emptied in place, so ids, order, groups and flags never change. It reads one leaf at a time through a read lease, copies the cropped pixels into a surface under their own raster reservation and releases the lease before the next leaf, so the peak is the cropped set plus one export; it refuses `stale` when the stacks, frame or any pixel guard moved meanwhile, admits one history entry for every before and after snapshot, and publishes one `replaceCanvasLayers` (same-id, same-type leaves, refused whole when any entry is invalid). `MergeLayerController` merges selected leaves into a new one through one pipeline parameterized by eligibility, result stack, result leaf and label: merge-selected flattens a contiguous raster run into a paint layer, merge-masks unions any inpaint masks' coverage (each at full alpha, since a mask's opacity only tints it on screen) into a mask configured like the topmost source.
- `MaskResultController`, `FilterResultController`, `GeneratedResultController`: guarded application-result adoption through narrow host ports.
- `ControlDerivationController`: control-layer intent patches and detected-map commits (see "Control derivation").
- `ControlViewController`: the display-only Original / Overlay view of one control layer (see "Control layer view").

Controller-local tests instantiate these boundaries with fakes. Integration tests in `engine.test.ts` cover composition, document routing, cross-controller invariants.

## Immutable document and raster snapshots

`CanvasDocumentCapability.captureSnapshot()` returns `CanvasDocumentSnapshot` or `null`. Snapshot holds structured clone of exact `CanvasStateContractV3` and engine's `documentGeneration`. Engine privately ties it to the reducer canvas identity it was captured from, so caller cannot manufacture a current snapshot by copying fields.

`CanvasExportCapability.captureRasterSnapshot(snapshot, layerIds, options)` requests exactly the required layer caches, temporarily pins them, reserves detached-surface capacity, copies their pixels into independent surfaces. Returns typed `ok`, `stale`, `aborted`, `not-ready`, `over-budget`, or `LayerUnreadable` (naming the first layer that could not be read) result. Freshness checked before and after every async rasterization boundary and once after all copies are detached.

`ok` result holds a `CanvasRasterSnapshot`: cloned canvas contract, its document generation, map of detached layer surfaces, idempotent `release()`. Snapshot is caller-owned. Its surfaces do not read live caches and stay valid while engine cools down; cooldown releases generation-scoped reservations but does not invalidate detached snapshots. Caller must release snapshot in `finally`. Engine disposal releases any snapshots still outstanding.

Snapshots create a deliberate transaction boundary:

1. Before detachment completes, document change makes capture `stale`; no downstream submission may use a mix of generations.
2. After successful invocation detachment, ordinary editing may continue. Composite, upload, graph compilation, queue submission read only frozen contract and detached surfaces.
3. Wholesale canvas replacement stays a separate session, identified by `documentRevision`; completed results from an older session are dropped.

Canvas invocation first crosses paint-flush barrier, then captures post-flush document, plans every raster/control/regional composite, and detaches exactly the contributing layers. Composite dedupe writes stage in transaction-local maps. They publish to persistent per-engine dedupe cache only after all frozen compositing, uploads, compilation, and queue dispatch complete; stale or failed captures leave no persistent dedupe entries.

`submitCanvasInvocationSnapshot` carries exact cloned canvas state used for compilation. `enqueueCompiledSnapshot` extracts its bounding box, dimensions, document revision instead of reading live project canvas. Generated candidates are placed from `queueItem.snapshot.canvas.document.bbox`, so later bbox edits do not move result. `documentRevision` still keeps results from a replaced canvas session out of current staging.

## Frame demand before allocation

Each frame is described once by a `CompositePreparation` (`render/compositor.ts`): leaves drawn bottom first, each leaf's effective matrix with transient transform overrides applied, isolated group scopes, each leaf's document-space bounds (persisted source bounds joined with any larger live cache rect, through that matrix). `compositeFrame` reuses the description until document identity, isolation or override contents change, and each leaf's bounds until its contract, matrix, live cache extent or document size does. Frame demand and screen composite read that one description; frame demand also keeps every filter-previewed layer resident, since its preview draws through layer's cache entry. Color sampler, overview and extraction prepare their own descriptions of committed document without transient overrides. The overview composites the same extent fit-to-view fits (the frame joined with every enabled renderable layer's bounds), translated so that extent fills its target, and returns that document-space rect so the Overview pane maps its outline and pointer through it. The screen description also carries which overlay stacks it shows: while a generation is staged (the staging area holds a candidate, shown or not, or a staged or progress preview is published) it hides the inpaint-mask and regional-guidance stacks and the regenerate-region tint, so the result reads untinted; control layers, isolation targets and every non-screen composite are unaffected. The flag is derived per frame, joins the description's reuse key, and its flip repaints in full once.

`calculateActiveFrameLayerIds` is the pure pre-allocation pass over that description: intersects each drawable leaf's bounds with document-space viewport. Explicitly isolated operation target is the one exception to normal document visibility: stays demanded and drawable when disabled or display-hidden, because user acts on that named layer directly.

Render path computes this set before `ensureLayerCaches`. Only demanded layers rasterize for the frame. Offscreen enabled layers are not eagerly allocated; they stay on-demand and LRU-evictable, then rasterize again when panning or a transform reveals them.

Frame's demanded layers form its working set. After drawing, `RasterController.enforceBudget` reclaims memory in fixed order (bounded or empty repaint reads only part of working set, so its usage window stays open from last full repaint):

1. derived and group artifacts the frame did not read (obsolete parameter variants, inactive groups);
2. least-recently-used base caches outside working set and unprotected.

Layer is protected while an operation pins it (`RasterMemoryBudgetController.pin`, held by every read lease, snapshot capture, export and duplicate) or while it is held: its pixels not yet persisted (`BitmapStore.hasPendingWork`) or an edit session (transform, text, float, pixel edit, operation lock) owns them. Whatever working set and protected layers still need stays resident; bytes above budget are reported as overage and leave no room for background reservations. Export and thumbnail callers request and pin their own caches. Deterministic tests assert allocation counts and bytes for pan/reveal, rotated bounds, unflushed paint bounds, isolation, transient transforms, eviction, re-rasterization.

## Raster resource ownership and memory policy

`RasterController` is the single raster owner. Owns base layer caches, derived and adjusted surfaces, group composites, decoded bitmaps, detached snapshot accounting, reservations and pins. Each store keeps a running byte total, updated at every allocation, resize, transfer and release, and pushes it to `RasterMemoryBudgetController`; nothing resynchronizes totals by rescanning. Cache surfaces change only through `LayerCacheStore` (growth, trim, replacement, `publishRasterized`, `captureState`/`restoreState`), so accounting cannot drift from pixels.

Raster soft limit is 512 MiB. Memory snapshot reports:

- `baseBytes`: layer cache surfaces;
- `derivedBytes`: derived and adjusted display surfaces;
- `groupBytes`: group composites;
- `decodedBytes`: leased `ImageBitmap` instances;
- `detachedBytes`: caller-owned raster snapshot surfaces and retained operation pixels;
- `reservedBytes`: capacity promised to background work but not yet represented by another class;
- `overageBytes`: amount the protected working set holds above the limit.

Background snapshots, thumbnails, raster exports, transformed/adjusted copies, and PSD exports reserve enough available bytes before allocating and return typed `over-budget` outcomes when they cannot.

Async raster reads return a `RasterReadLease` (`rasterTransactions.ts`): pixels, their layer-local extent, a freshness guard, an idempotent `release`. Lease pins its source layer from before rasterization until release, so neither eviction nor paint trimming can reshape pixels an operation is still reading (persistence encodes a pinned layer untrimmed instead of waiting); guard still rejects pixels a later edit replaced. Leases on detached copies (adjusted or baked pixels) release source pin as soon as copy exists. Extraction, merges, crops, copies, filters, snapshots and composite exports all read through leases and release them in `finally`.

Reservations are idempotent leases. Cancellable preparation work uses lifecycle-generation reservations, which activation, cooldown, and disposal release if normal `finally` path has not released them. Once an async raster composite is in flight, it uses operation-owned reservations instead: lifecycle changes may make its result stale but cannot erase its accounting while a yielded allocation can still resume. Pins are always operation-owned. Detached snapshot accounting follows the snapshot; only `CanvasRasterSnapshot.release()` or engine disposal releases it.

Paint persistence protects dirty pixels until their latest generation is acknowledged: across encoding, upload failures, an open retry circuit and later strokes. Dirty paint layer whose cache is missing keeps its pending work and fails flush barrier; store never reports a save that uploaded nothing.

`DecodedBitmapPool` replaces permanent decoded-image caching. `acquire(imageName, decode, signal)` refuses an already-aborted request before any work starts, coalesces concurrent decodes for same image, returns a short-lived `DecodedBitmapLease`. Each rasterizer releases its lease in `finally`. Bitmap closes after final lease; pending decode aborts when all interested callers cancel and its late bitmap is closed; pool observes its own decode promise so an abandoned decode cannot surface an unhandled rejection; disposal aborts pending work and closes every resolved bitmap. Pool byte changes feed `decodedBytes`.

Staged results use a separate compressed-Blob cache instead of retaining a decoded surface for every candidate. Once a candidate's thumbnail settles, UI asks engine to prefetch its full-resolution bytes, at most two full-image requests in flight. Selecting a queued candidate promotes it immediately and preempts stale work; completed/in-flight requests and concurrent decodes of same image coalesce. Per-engine cache is LRU-bounded to 24 entries and 64 MiB, retries a failed selected request once as foreground demand, releases outstanding work on engine cooldown or disposal.

## Composition, damage and overlays

Damage is explicit: `FrameDamage` is full repaint, no visible repaint, or layer-local regions. Scheduler widens to full on any invalidation without a region, a viewport change or a forced repaint. Compositor resolves regions through frame's matrices into one padded screen rect: regions entirely off target draw nothing; bounded repaint clips to the rect and culls every leaf, group scope and staged preview whose screen bounds miss it. Unknown layers or non-finite geometry repaint everything.

Compositing always renders through canonical `RasterBackend`; no approximate backend-free path. Filter previews and floating selection of a grouped member compose inside group's isolated surface, under group's opacity, blend and adjustments, exactly as member's committed pixels would. Committed content composes with same semantics for display, sampling and export; previews and floats are display-only. Layer's own adjustments apply to its layer-local pixels before resampling: export draws display's memoized adjusted copy of a leased live cache when one is current and exact, never building one (a layer-sized copy would exceed the export's reservation), and otherwise adjusts only the layer region the output samples (plus one pixel of resampling margin). When a downscaled layer samples more pixels than output holds and its stack is position independent (color only), a detached copy of it is adjusted after resampling instead, keeping export work bounded by output size; composite reservations count each such scratch buffer at output size. A position-dependent stack (noise) never takes that shortcut: resampling must average its grain exactly as on screen, so its layer-local sampled region is adjusted and reserved even when larger than the output. Composite reservations plan that region from estimated content bounds; when a layer's rasterized pixels (measured text) sample more, rendering reserves the excess before allocating it and refuses as over-budget when it does not fit. World-space bakes (merges, boolean merges, crops, copies) and PSD always adjust the layer's own stack on a layer-local copy, or draw the display's exact adjusted copy, and then resample it. Merge Down bakes both layers' own stacks the same way before the upper layer resamples into the lower layer's space, so the merged layer carries no stack; its undo snapshots stay raw and undo restores both layers with their stacks. Control layers carry no stack, so a raster layer whose stack changes pixels reaches the control stack only baked: copy to control (`CopyLayerController`) and convert to control (`LayerMutationController.convertToControl`) draw the layer's exact baked export at an identity transform, conversion in place as one step whose undo restores the raster contract, its stack and its original cache; a layer whose stack changes nothing, or an empty layer with no pixels to bake, takes the plain contract clone of source and transform. Mask conversions read alpha alone, which no adjustment writes. Rasterize bakes a position-dependent or spatial stack (all of it) into the layer-local source render before the transform and drops it from the paint contract, since kept it would grain, or measure detail on, the baked pixel grid; a color-only stack stays on the contract. Thumbnails downscale the display's current adjusted copy when one exists.

Per-pixel adjustments (every type except the spatial ones below) are position dependent but region independent. `applyAdjustments` takes the pixel of its ImageData's top-left in the stack's reference space; adjusting any sub-rectangle at its own origin yields exactly the pixels a whole-surface pass gives there, which damage refreshes, sampled regions and group-region repaints rely on. Color entries ignore position. Noise adds a field that is a pure function of seed, integer pixel coordinate and channel (a stable integer hash into an equiprobable quantile table, no sequential state), scaled per pixel by a function of that pixel alone: 1 for `flat` response, 4·Y′·(1 − Y′) of the incoming Rec. 709 luma for `midtones`. Size 1 adds the white samples directly. Larger sizes blur them with a separable Gaussian of σ √(size² − 1)/2 truncated at 3σ (R taps each side), renormalized so squared taps sum to one (σ unchanged); a kernel whose outer taps all stay under 10⁻³ (sizes under about 1.14) runs as size 1. Samples beyond the ImageData come from the hash, never from pixels, and each output sums the same float64 values in the same order wherever the region starts, so region independence stays exact. The blur streams rows through a ring of 2R + 1 horizontally filtered rows: transient JS heap of O(R × width) per channel, not counted in the raster budget. Cost is O(pixels × R × channels) on the main thread, paid once per changed preview frame while a slider scrubs. Monochrome shares one field across R, G, B; color draws three; chroma draws two, added to OKLab a and b with lightness kept, then converts back to sRGB clamped in linear light. A layer's own stack works in layer-local pixels (cache surface (0,0) is `entry.rect`'s origin, possibly negative) and is always applied before resampling when it contains noise, so display, generation, exports, bakes and PSD agree in grain pattern and strength, and the grain moves with the layer under transforms. A group stack works in document pixels: group surfaces, composite group buffers and PSD's baked group stacks all sit on the document grid at scale 1. The one exception is a floating selection: its display copy is baked at its lift origin and moves with the drag; committing recomputes the layer's grain at the new position. Thumbnails without a current display copy adjust their own downscaled pixels, shrinking grain to size × scale (at least 1) and scaling σ by min(1, scale × grain span) to approximate the averaging a downscale applies; span is (Σ taps)², 1 at size 1.

### Spatial adjustments

Clarity, texture and dehaze are spatial: an output pixel depends on OKLab lightness across a neighborhood of the owner's source, so they are neither per-pixel, region independent, nor resample-commuting. Their domain is the source's alpha bounds, computed inside the kernel (`render/spatial/evaluateSpatialSteps.ts`): hidden pixels borrow the nearest visible pixel's lightness, and nothing outside the bounds, no hidden pixel and no alpha is written, so any buffer holding all the content gives identical pixels. They therefore evaluate only on the owner's full source in owner pixel space (a layer's cache surface before its transform, a group's document-resolution composite), never on a sampled, cropped or downscaled region. `applyAdjustments` skips them; `toSpatialPlan` splits a stack into ordered runs, per-pixel runs applied on the main thread at the owner's origin and each run of consecutive spatial entries sent as one job to `SpatialAdjustmentService`, a module worker evaluating one job at a time.

Display is asynchronous, run by one state machine per owner (`render/spatialDisplay.ts`) that layers (`render/adjustedSurfaceCache.ts`) and spatial group scopes (below) share. While a layer's job is pending its adjusted surface shows an interim: a parameter change keeps the shown pixels; a content edit with known damage re-patches that rect with the per-pixel part only; unknown damage, a new source or size, or a rebuild after eviction shows a whole per-pixel-only interim. A layer has at most one job in flight and a later target waits for it, so scrubbing reads the source once per landed result. A content change starts the next job after 120 ms of quiet, anything else as soon as the running job ends; a placeholder cache with no published pixels starts none. A result installs only onto the same source surface, from a version at or before the shown one whose later damage is known (re-patched per-pixel after the install), and only when newer than the result shown, so an older parameter's result can land as an interim while scrubbing. The copy is exact only when the installed result's version and key both match the current ones. `peek` returns exact copies only (export reuse, merges, control-pixel materialization, which refuses `not-ready` meanwhile); `peekDisplayed` returns whatever is shown (thumbnails). Installing calls the engine's settle handler, which recomposites the layer, steps its thumbnail display token and the pixel epoch (overview) and marks ancestor group surfaces for a full redraw, since no cache version changed; it never drops the surface that landed. A status leaving `computing` without a landing (failure, eviction) also redraws ancestor groups, which may be waiting on it. After `too-large`, `over-budget` or `error` the owner shows the target's per-pixel part only (repainted when that part differs from what is shown, then settled like a landing) and retries only after the target changes: `too-large` depends on the content's alpha bounds alone, so only new content retries it, never a parameter scrub; the others also retry on a parameter change. The keyed `adjustmentStatus` store (`interaction.getLayerAdjustmentStatus`) reports those and `computing`; absence means exact. Control-pixel materialization refuses `not-ready` while the owner computes and an `AdjustmentRefusal` naming it once it cannot run. A floating selection previews the per-pixel part only and committing re-evaluates the layer. Layer deletion, base-cache eviction and disposal abandon spatial work; the engine also drops the spatial state of layers and groups that no longer draw a spatial stack, drawn or not (`retainSpatial`, visiting only owners that hold such state), so no status outlives its stack. Cooldown abandons only the display's running and scheduled jobs, dropping their interims; exact copies and failures keep their state, and pixel-writing operations' jobs stay governed by their own signal, since their detached snapshots outlive cooldown.

Each job reserves its 4 B/px pixel buffer as an operation-owned `spatial-adjustment` reservation until the buffer returns from the worker; `over-budget` refuses the job. Worker scratch (up to `SPATIAL_SCRATCH_BYTES_PER_PIXEL` per alpha-bounds pixel, at most `MAX_SPATIAL_PIXELS`, about 400 MB at the cap) stays outside the raster budget: the budget accounts surfaces resident in the page's heap, while scratch lives in the worker's, one job at a time per engine (each engine owns its service and worker), freed when the job ends or the idle worker terminates after 30 s. Counting it would evict display caches for memory the page never holds.

Pixel-writing consumers evaluate spatial stacks exactly or refuse; none leaves a spatial entry out. `render/exactAdjustments.ts` applies a stack's per-pixel runs on the calling thread and sends its spatial runs to the shared service at `now` priority, one slot per job so consumers never supersede each other. `too-large`, `over-budget` or `error` becomes an `AdjustmentRefusal` naming the owner and cause, returned through each operation's result: generation (its notice), exports, layer bakes and everything built on them (filter and Select Object sources, crop, copy, boolean merges, Run Workflow, clipboard and board saves), Merge Down, Visible and Selected, Rasterize, conversion to a control layer, PSD and extraction. A consumer reuses a layer's display copy only when exact; groups have no exact peek, so a spatial group scope always runs its own job.

The raster composite (generation, export, extraction) evaluates a spatial leaf on all its leased pixels in layer-local space, then resamples it, never through the sampled-region or post-resample paths. A spatial group scope leases its members first, composites them over the union of their actual bounds (the display's group surface domain), unclipped by the bbox, evaluates its stack there in document pixels and lands at its offset; nested scopes draw into that frame. Pixels inside a bbox therefore do not depend on the bbox. Composite reservations count a spatial leaf's whole planned content and a spatial scope's planned member extent, each with its ImageData; the job's buffer is the service's reservation, and larger actual extents (measured text) reserve the excess while rendering. Extraction composites its leased contributors through this path instead of the display's providers, so it never reads an interim or takes a group slot.

Layer bakes (`RasterExportController`) adjust the whole layer-local copy and then recheck the lease guard, since a job yields. Merge Down and Rasterize are asynchronous: the transaction stays open across the job and lands only if the edit revision, the caches and their versions, and any display copy drawn are unchanged, otherwise `not-ready`. Merge Visible evaluates a spatial group stack on its merged-rect buffer, which holds every member, and lands only while every contributor's guard holds. Colour sampling, the overview and thumbnails mirror the display and may show an interim.

Group surface is keyed by everything except its members' pixels and float's placement (scope shape, member appearance and matrices, in-scope previews, float's surface). While that key and bounds hold, cache refreshes in place: it unions damage each member's cache recorded since the version it last drew, padded by one source pixel before member's matrix maps it (bilinear reach at any scale), plus old and new landing of a moved float, clears that region with one pixel of antialiasing margin and redraws every contributor there, then applies group's adjustments to the region alone, at the region's document origin. Unknown member damage, a member's landed spatial result (`invalidate`), changed member set or new bounds redraw whole surface, reallocating only when its size changed; new key reuses least-recently-used of a group's two slots once both are taken.

A scope whose own stack is spatial keeps its slot surface raw (its own stack key stays out of its shape key, so a parameter edit repaints nothing; a parent still keys it as a child). Each raw repaint bumps the slot's raw version and records its surface-local damage: unknown for a whole rebuild, and only member content damage for an `invalidate` redraw, so the adjusted copy keeps its pixels until the group's own result lands. It tracks each member's and nested group's look (stack, opacity, blend, matrix) apart from its shape: a look change repaints that look's old and new bounds in a same-shaped slot with the same bounds. A spatial stack edited into another spatial stack is redrawn only in the raw composite, not patched in the adjusted copy, since its shown pixels stay until it lands. A move that changes the group's bounds repaints the whole slot. A same-size adjusted surface, counted in group bytes and evicted with its slot, follows the layer rules on that raw composite: the domain is the document-resolution union of member bounds, whose transparent margin the kernel's alpha-bounds domain ignores, and per-pixel runs work at the slot's document origin. Each slot runs its own jobs; the group reports, under its id in `adjustmentStatus`, the status of the slot the canvas frame read last (else of its most recently read slot), so reads by the overview or picking under other keys never flip its row or redraw its ancestors. While a filter preview, float or transform session gives the frame and the overview different keys, each runs its own job on its own inputs: a known cost, not a correctness issue. A raw repaint trail longer than 16 entries folds its oldest entries together, so damage since an older version stays known, only coarser. A job waits (reporting `computing`) while any member's or nested group's displayed pixels are still pending; a member that cannot finish does not block it. Every read returns `state`, `exact`, `pending` or `inexact`, combining the group's own state with its inputs'. The group's settle handler steps the pixel epoch and redraws ancestor groups and the frame, never the landed group. The engine drops the spatial slots of groups that no longer draw a spatial stack (`retainSpatial`), clearing their status.

Overlay renders in CSS pixels. Receives document→CSS view, CSS viewport size and device-pixel ratio, clears backing store in device pixels, then draws every handle, nub, dash and cursor under a DPR base transform (nested image and path transforms compose with it), so chrome keeps its CSS size at any ratio and matches CSS-pixel hit tests. Viewport owns the ratio (capped at `MAX_DPR`, sub-one ratios kept); backing-store size and composite view matrix both derive from it.

Color picker shows a loupe of pixels under the pointer. Anchors to pipeline's last pointer position in screen space, so pans and zooms keep it under pointer, and shows as soon as picker activates over a still pointer. Each overlay frame composites the square around that point through same sampler, providers and coverage rules as a pick, so magnified center pixel and its RGB readout are exactly what a click picks; square holds fewer, larger pixels once canvas zoom passes loupe's own magnification. Hover chrome (loupe and brush ring) leaves canvas with pointer unless a gesture still owns it; input handlers are stable so detach removes every listener attach added.

## Derived surfaces and invalidation

Every display-only pixel effect uses `DerivedSurfaceCache`. Slot identified by layer ID and effect kind, guarded by source surface identity, monotonic source version, and a deterministic parameter key. Reuse safe only when every guard matches. So source replacement cannot publish or reuse a surface produced for an older preview. A spatial stack's adjusted surface also records whether its pixels are exact or an interim (see Spatial adjustments).

Invalidate only affected effect when parameters change. Delete every derived slot when a layer is removed, replaced, or its base cache evicted. Frame-demand culling happens before derived lookup or construction.

## Edits, history and replay

Every recorded document and pixel edit goes through one protocol, `CanvasMutationContext.begin`, and is admitted before it mutates anything. Admission reserves undo entry's bytes in `History` without clearing redo or evicting older steps, so an edit whose entry could never be kept is refused as `over-budget` with document, pixels and history untouched. Two kinds of edit are admitted before they change anything but publish afterwards: live strokes paint as they are admitted (see below), and floating selection holds its admission from lift to landing. Selection-mask changes (`selection/selectionHistory.ts`) admit their step right after applying, because new mask's size is only known then, and roll back to exact prior selection when it cannot be kept. Resulting `EditTransaction` also reserves raster memory for its preparation (`reserveRaster`), holds leases and pins until `end()`, publishes once: `publish(label, step, entry)` applies an `EditStep` — optional document mutation with its postcondition and rollback, prepared pixels to install, ancillary notifications — verifies reducer and mirror, records the entry, then routes a user edit and notifies. Step that is rejected or fails its postconditions records nothing; failed postcondition dispatches step's rollback and reports when reducer or mirror could not return. Transactions refuse while permit is stale, a gesture runs (unless edit belongs to that gesture), a replay runs, or engine is disposed. Coalescing (nudges) names the entry it replaces by its `HistoryEntryToken` and is refused once anything else became newest step.

Layer controllers build their steps from `controllers/editSteps.ts`: byte accounting, replay reservations (replay whose preparation memory does not fit throws `REPLAY_RASTER_REFUSAL` and stays in place), steps that add, replace (one layer, or several as one `replaceCanvasLayers`, sharing the identity postcondition, rollback and pre-install hook) and remove layers with their prepared pixels, and new paint layers. It also names how a publication that did not land is reported: ordinary layer operations (merge, crop, copy, rasterize, insert) report reducer refusal or failed postcondition as `failed` (`layerOperationStatus`), while guarded result operations (generated, filter, mask and staged results, mask edits, duplicate) report it as `stale` (`guardedResultRefusal`), because their target moved on after the guard was taken.

Floating selection (`FloatingSelectionController`) computes its commit footprint from geometry before it copies or cuts anything: before and after pixels over union of hole and landing, selection alpha before and after, entry overhead. Admitted for that footprint as part of the drag that lifts it; keeps the transaction until it lands or is dropped. Every move, scale or rotation grows admission to the footprint at the new transform, from geometry alone; transform that does not fit keeps last accepted one and reports `over-budget` once per float, so an accepted transform always fits its undo entry while permit stays current; admission never shrinks, so a live float holds its largest accepted footprint until it lands or is dropped. Refused lift is reported and moves nothing (`lift` returns `refused`), including content whose cache is not rebuilt yet; only a lift with nothing to take (`unavailable`) lets Move tool fall back to moving the layer. Cut layer's persistence is suspended while float lives. Commit lands pixels and moved selection as one entry under retained admission, renewed once when its permit went stale (an operation locked and released the document meanwhile); commit that cannot be admitted or published puts pre-lift pixels and selection back. Cancellation refills hole before persistence resumes; hole that cannot be refilled keeps layer suspended rather than uploading it. Every terminal path ends the transaction: commit, cancel, Escape, undo/redo, layer's deletion or replacement, document replacement, cooldown (which banks the float before the flush), disposal, exceptions while cutting or landing.

Live pixel edits (brush, eraser, shapes on paint layers or as opaque mask coverage, pixel transactions on control and image layers) are admitted before their first pixel changes and grow their admission before the stroke's before/after footprint does; refused growth restores layer's pixels and extent and engine reports the refusal through `tools.onEditRefused`, which canvas widget turns into a notice. Tools report a press the selected layer cannot take there too, as a `CanvasLayerEditRefusal` naming the layer: hidden (disabled, itself or through a group), locked, transparency-locked under the eraser, or its durable pixels not in the cache yet (the press requests them and the next one can edit; nothing is drawn over missing pixels). The Brush never creates a layer above a locked or hidden image on its own; its refusal offers one. Brush, eraser and move cursors read not-allowed over such a selection; the engine refreshes the cursor on every document change. Widget previews of structural edits run in one owned `StructuralPreviewSession` (`useStructuralPreview`), which coalesces live dispatches to one per frame, captures the values its first preview of each field replaces (session's baseline) and records the gesture as a single step from it; refused commit or cancel restores that baseline, even while edits are locked. A commit from elsewhere, a history replay, a newer session or disposal ends an open session first, dropping pending previews and restoring baseline, so previewed values never land over a replayed document or inside another step: every engine edit starts from `CanvasMutationContext.getDocument()`, which ends it first (structural controller's commits and nudges, pixel and layer operations such as merge down and duplicate, result commits); widget-prepared edits (`commitPreparedEdit`, layers tree's child-row commands) end it before reading the model; `HistoryController` ends it (with any live float) before a replay that has a step to land, and a replay with nothing to land disturbs nothing; document replacement drops it without restoring, since the document it previewed on is gone. Widget's next preview starts a new session from changed document, and a commit after engine ended its session records from live values; its refusal as `missing` stays silent, since the document change that ended the gesture also unmounted the editor.

Undo and redo are async and failure-atomic: entry moves to the other stack only after its replay completes, replay that throws leaves it in place and is reported, and edits and new gestures are refused while one runs. Replays apply steps through same verified path (`applyStep`). Pixel replays land only on trustworthy pixels: evicted or stale cache is rasterized first under a read lease, and a layer that no longer exists moves the step as a no-op.

## Edit leases and staged-result acceptance

Application operations acquire one exclusive lease from `CanvasEditGate`. Lease carries an `AbortSignal`, has explicit `isCurrent()` freshness check, is idempotently released. Release, document/project invalidation, cooldown, or disposal aborts and stales the lease. Expected cancellation and stale results use status unions; exceptions represent unexpected failures. Operation sessions publish typed error codes, not copy (`FilterSessionError`, `SamSessionError`): view translates the code when it renders, so a visible error follows a language change, and an unexpected failure shows a translated summary with its original message as technical detail.

Staged-result acceptance is engine-owned. UI enables Accept from interaction capabilities, but `StagedResultController` stays authoritative. It captures a document-edit permit, rejects an active gesture, verifies selected candidate's stable key immediately before dispatch.

Initial `commitStagedImage` mutation atomically inserts new raster layer at top of raster stack, clears staging, records project event. It keeps a selected overlay leaf (inpaint or regional mask, control layer) as editing target while next stroke could edit it (leaf and every ancestor enabled and unlocked, as painting requires) and otherwise selects new layer: nothing, a group or a refusing leaf was selected, or raster work the result now covers; `selectionAfterAcceptedResult` (`document/selectionRepair.ts`) decides this once for controller's postcondition and history steps, the reducer, and its rollback. Controller verifies both reducer postcondition and document mirror before pushing exactly one engine-history entry. Returns `busy`, `stale`, or `missing` without changing staging or history when any guard fails.

Canvas widget stops candidate's originating batch only after an accept has committed (`widgets/canvas/stagedAcceptance.ts`), and only while that batch still has queued or running work the queue can cancel; action keeps its ordinary "Accept to layer" label. Request is Workbench reducer action `cancelQueueItem` (exposed as `queue.cancel`) with an accept-specific notice in place of the generic cancellation one, or none (`notice: null`) when the accept set other candidates aside: its own notice then says the batch stopped beside an Undo that re-stages those candidates (`restoreStagedImages`, fenced by `documentRevision`; `widgets/canvas/useCanvasRecovery.ts`). Discard, Discard all and the Delete key report the same way; Discard all also stops this canvas session's queued or running generations and keeps a restore point of the results. It marks batch cancelled at once, so it shows as cancelled in queue and siblings that finish before backend stops are dropped instead of re-staged; queue runtime then cancels by batch id, retries a failed request, reports the failure once per batch. Other batches untouched, continue-staging save never stops generation, undoing accepted layer re-enqueues nothing.

Continue-staging variant uses same guarded transaction but inserts candidate as a disabled raster layer, preserves exact staging-area state and current layer selection, keeps staged preview active. Lets users bank candidates without visually doubling preview or ending comparison. Undo and redo affect only the banked layer after initial transaction.

Undo removes accepted layer and restores prior selection. Redo restores identical layer and selection without recreating event or staging candidate. History entry replays failure-atomically; successful commit publishes through an admitted transaction, which clears any previous redo stack. Undo intentionally does not return accepted candidate to staging: staging is reducer data a later result may have changed, so an engine step never rewrites it; the accept's notice says so.

### Restore points

`canvas.snapshots` are restore points, at most `MAX_CANVAS_SNAPSHOTS` (five) per kind and project, newest kept, so Discard all points never push a `clear-canvas` point out. Every document swap they drive (`widgets/canvas/canvasRestorePoints.ts`) crosses the paint barrier first and changes nothing when the flush fails: Clear canvas keeps a `clear-canvas` point of the document and its staged candidates (none for a blank canvas: no layer but empty masks, no candidates), then replaces the document and withdraws the point when `replaceDocument` refuses. Restoring a canvas point, from the History pane or a toast's Undo, waits while `documentEditingLocked` or the generation lock holds the canvas (a swap would drop that session's in-flight and staged results) and says so. `document.restoreSnapshot` is the one restore path, a document swap like `replaceDocument`: `restoreCanvasSnapshot` bumps `documentRevision`, clears staging (restoring the point's candidates when it kept any) and so drops in-flight results of the replaced session, and engine history clears with the swap. `keepCurrentAs` saves the replaced canvas as a point in the restored one's place, so a restore is undoable without pushing an older point out; a blank replaced canvas is not kept and the restored point is deleted instead. Discard all keeps a `discard-results` point of the candidates only, its document an empty one of the canvas's size; restoring it neither waits nor flushes, re-stages the candidates on the current canvas through `restoreStagedImages`, leaves the document alone and is used up once one of them is back (when all already are, the point stays and nothing changes). A staging Undo re-stages through `restoreStagedImages` fenced by the discard's `documentRevision`; after a swap moved it, Discard all's Undo falls back to its point and the others say they could not bring the results back.

## Control derivation

A typed control layer can keep the pixels it was detected from (`original`, framed by `originalTransform`) beside the derived map in `source`. The invariants are documented on `CanvasControlLayerContract`; `document/controlDerivation.ts` owns them as pure rules, and every engine path that changes a control layer's pixels or frame applies one of them so no edit leaves a map paired with an original it no longer derives from:

| Operation                                                         | Rule                                                                                         |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Materialize before a pixel edit (`buildMaterializedPixelLayer`)   | `rebaseControlOriginal` with the baked transform; a frame the bake would shear detaches      |
| Transform Apply baking a paint map (`TransformEditingController`) | the same rebase in the bake's own step, so undo restores the whole before-contract           |
| Crop to bbox                                                      | detach (the cropped pixels become the image)                                                 |
| Generated or Select Object result replacing a control layer       | detach and drop `filter`: the result is the image, not a filter's map                        |
| Filter result on a control layer                                  | refused `unsupported`: Filter runs on raster layers only; a control map comes from detection |
| Filter result copied from a raster layer to a new control layer   | a fresh control layer; `controlCopy.controlType` types the copy with `detection: null`       |
| Paint on a map that needs no materialize                          | only `source` changes; the map stays current                                                 |

`ControlDerivationController`, reached through `CanvasApplicationHost` (`captureControlDetectionGuard`, `commitControlLayerPatch`, `commitControlMap`) like the Filter, Mask and Generated adoptions, is the only writer of derivation fields besides those rules. The application's detection coordinator calls `commitControlLayerPatch` for an intent (type, detector, settings, image) and `commitControlMap` for a detection result, guarded by `captureControlDetectionGuard`: same `documentRevision` and same `controlDetectionInputKey`, which ignores weight, name and paint on the map, so those never discard a running detection. Neither commit passes the operation edit owner. A detection runs in the background while the user keeps working, so its commit must yield to whatever holds the document: an operation's lease (Filter, Select Object, Transform), a gesture, a replay or a session holding the layer's pixels all refuse it `busy`, and the coordinator retries once the lock releases. The guard capture and the map commit's freshness checks (before decoding, after it, and once admitted) read the reducer document, so a background job never ends the user's structural preview; only an admitted commit does, and the map is built from the layer as it stands after that. A map whose input is the layer's own unpersisted paint is also `busy` until `flushLayerUploads` lands those strokes in the `original` it records. The commit promotes the map image through the caller's `makeDurable` only once its first check passes, just before decoding, and promotes it once across retries: promoted maps are exempt from server-side intermediate cleanup, so a result that is refused, superseded or dropped as stale before then stays collectible. A refusal after promotion (stale after decoding, over-budget, a history refusal, a busy timeout) still leaves that map durable and unreferenced; this is accepted because detector graphs cache their results, so a re-run can return a map the document or history still references and deleting a dropped one could remove a live map. A document change (undo, redo) that leaves a layer needing no detection, or changes its input other than by its own paint landing, cancels that layer's run and its backend queue item, except while that run's own map commit is in flight, whose publish reconciles synchronously.

History pairing keeps one undo per user intent. A patch with a `coalesceKey` replaces the newest entry while that is the controller's patch of the same layer and key, so a settings scrub is one step. A map replaces the newest entry while that is the controller's entry for the same layer that requested this input key (a patch that changed the detection input, or an earlier map), so one undo reverts "set type" and its map together; otherwise the map records its own "Detect <type>" entry, and a weight or name patch in between is never undone together with a later map. The controller's record of its newest entry, including any unpersisted before-pixels, is dropped when that entry is disposed (evicted, cleared, discarded from redo or replaced), so it never outlives the entry. Patches route as user edits; maps publish as `system` so a background result never changes the invocation route. Undo restores the exact before-state: a contract whose source is persisted re-rasterizes from it, and unpersisted paint the step replaced is captured and replayed with the entry. A source change discards the outgoing source's pending persistence. Undo and redo never schedule detection; a restored stale map shows as needing detection until the user asks again.

### Control layer view

`previews.setControlLayerView(layerId, 'original' | 'map' | 'overlay')` lets the user compare a control layer's map with the picture it was detected from. `ControlViewController` owns the one view that can exist. It refuses while an operation holds the document (`documentEditingLocked`) or a generation or staging locks the canvas (`setInteractionLocked`). Otherwise it reserves raster memory for the original's decoded pixels, rasterizes the `original` source with the layer rasterizers, and once the surface exists accounts it as detached pixels until the view ends; the reservation ends with the decode. `map` ends the view and resolves `shown`.

| Outcome       | Meaning                                                                                |
| ------------- | -------------------------------------------------------------------------------------- |
| `shown`       | the view (or the map) is displayed                                                     |
| `missing`     | no control layer with a kept original that has pixels                                  |
| `locked`      | an operation or a generation holds the canvas                                          |
| `stale`       | a newer request, a reset below or an edit of the layer superseded the decode in flight |
| `over-budget` | the original's pixels do not fit the raster budget; nothing was decoded                |
| `failed`      | the original could not be fetched or decoded                                           |

The view records the contract it was built from and publishes `{ layerId, view }` as the `controlLayerView` interaction state. It returns to the map (`null`, surface released, layer invalidated), ending any decode in flight, on:

- any change to the layer's contract (every edit, undo, redo and detection commit) and its removal;
- another selection;
- a stroke or other pixel edit admitted on the layer (strokes paint the map live), a direct repaint of it, and its cache invalidation (including `clearCaches`);
- the editing lock or the interaction lock engaging;
- document replacement, the project going away, cooldown and disposal.

The compositor draws the original as layer-local pixels, like a floating selection: through the layer matrix and `originalTransform`, at the layer's opacity and blend, without the control-transparency effect. `original` draws it in place of the map, even when the layer has no map; `overlay` draws the map over it at `CONTROL_OVERLAY_MAP_ALPHA` of the layer's opacity. The original's landing joins the leaf's bounds, so culling and bounded damage cover it. Control layers never sit in a composited group scope (only raster-stack groups composite in isolation), so group surfaces never see a view. Isolation suppresses it, and only screen frames pass it: history, persistence, thumbnails, exports and generation composites read the map.

## PSD export

PSD export is a planner/executor transaction over immutable snapshots. `PsdExportController` captures one `CanvasDocumentSnapshot`, walks raster tree into planner inputs (groups as pass-through folders, exportable leaves with their captured content rects), then obtains a `CanvasRasterSnapshot` including disabled layers. `planPsdExport` reverses every level of top-first tree into ag-psd's bottom-to-top order, writes each node's own visibility flag (disabled group is a hidden folder), flattens merged preview from the leaves that contribute (enabled with every ancestor enabled), which is what Photoshop renders for the same flags. Folders whose subtree exports nothing are dropped. Execution reads only detached surfaces; cannot mix live layer caches from different document generations.

Each leaf bakes its own stack exactly (spatial entries included), layer-local, before the transform. PSD has no group adjustments, so each enclosing group's stack, innermost first and named per group for refusals, is baked into each leaf's world pixels: under member opacity and blending, and for spatial entries, which see that leaf alone instead of the group composite, this approximates the canvas.

Controller keeps 30,000-pixel side cap and also derives a pixel-area limit from currently available reserved bytes. Accounts for flattened composite plus each transformed layer surface, budgets eight bytes per required pixel, reserves full execution allocation before creating PSD surfaces. Final freshness check happens before that reservation; once execution starts it uses only frozen pixels. Capture and execution reservations release in `finally`; cancellation aborts before next allocation or side effect.

Capability returns `exported`, `nothing`, `too-large`, `not-ready`, `over-budget`, `stale`, `aborted`, a `LayerUnreadable`, or an `AdjustmentRefusal`. Layers widget awaits the promise and maps every non-success result to a user-visible notice.

## Input ownership and frame scheduling

Pointer pipeline (`input/pointerPipeline.ts`) owns gesture capture and temporary holds (Space → view, Alt → picker, C → bbox). Keyboard ownership is explicit. Widget passes its focusable keyboard root and a `resolveKeyOwner` judge to `surface.attach`; the judge names the workbench region that owns a keydown (`surface`, a `companion` widget acting on this canvas's layers, or `elsewhere`) and is asked only on keydown, after the pipeline's own refusals, so the engine imports nothing from Workbench focus and pointer paths never pay for it. No key acts over an editable field, a control reached by keyboard (pipeline records on `focusin` whether focus arrived by pointer: Chromium marks focused element `:focus-visible` at any keydown, so arrival is the only reliable signal), an open dialog, menu or listbox, or beneath a modal. Past those refusals: Enter applies a session only from the `surface` with focus on its root or nowhere, never on a control; the Escape ladder and C act from the `surface` or a `companion`; Space and Alt stay pointer-led, acting over the hovered canvas whatever the owner and otherwise only from the `surface`. Without a judge (tests, detached engines) focus alone decides: the root or no focus is the surface, and a control the pointer last clicked counts as a companion. Owned Space keydown is prevented, so a clicked control does not activate. An owned Alt keydown is prevented, and so is the release of an Alt the pipeline claimed, because Firefox and Windows otherwise activate the menu bar; that holds for a tool that reads Alt as a gesture modifier too (Marquee, Lasso, Move and the Frame tool's grid bypass, Transform's scale about the centre), which keeps the key and only gets no picker hold, since pointer events still carry `altKey`; the Color picker tool (I) covers those tools. Every other release is observed, never consumed. Alt from the surface while the pointer is elsewhere arms a pending hold that the next `pointerenter` with Alt still held, or a `pointerdown` with Alt, begins before the press is routed, so a pen landing without hover samples on contact; release, tool switch, blur, reset and detach clear it. Genuine tool switch first cancels the gesture through outgoing tool and ends any hold, restoring held tool, so the switch leaves the tool the user was really on and a later key release restores nothing.

`ColorSampleController` routes picks. A pick previews each sampled color to the one-shot request or the workbench router (`setColorSampleRouter`), then commits the last preview once on release or cancels it once when the press ends any other way (Escape, a tool change, a cancelled pointer); a declined preview falls back to the brush color. The sink that took a pick's first preview gets its commit or cancel, so a request armed or settled mid-pick never sends the router a stray phase, nor the reverse. Brush and eraser share an engine-lifetime memory (`PaintLineEndController`) of where the last committed stroke ended on each layer, kept in that layer's local space: a Shift press on a layer with a remembered end draws a straight segment from it, placed through the layer's current transform, as part of the one stroke. The engine routes every layer change to it. A change of transform alone (move, nudge, Fit to frame, a transform parameter) carries the end with the layer; a change that rewrites content and transform together (crop, conversion, a baked float or result) keeps its document position and re-expresses it in the new local space; an applied Transform on a paint layer, which redraws only the pixels, rebases it from the session's transform. It survives tool switches but forgets on replay, document replacement, the layer's removal and a transform it cannot invert. `layers.beginTransform` (`TransformEditingController.request`) selects a leaf, switches to transform and opens its session even when transform is already active, cancelling a session on another layer; it refuses a locked or ineligible leaf, a running gesture, a live float or locked edits without changing selection or tool. A leaf whose only content is a stroke persistence has not acknowledged yet (a new paint layer's first upload) has no persisted extent to frame, so the request waits in the `pendingTransformLayerId` interaction store and the session opens when the bitmap lands, while the leaf is still selected, transform is the tool the user is on (a Space, Alt or C hold over it counts) and no other session opened. The wait ends without a session on a genuine tool switch, a selection change, the leaf's removal, Escape, a history replay, a document replacement, disposal, or an upload of that leaf failing with no retry to follow (retried failures keep the wait), which also reports a `not-ready` refusal through `tools.onEditRefused`.

`RenderScheduler.beforeNextFrame(task)` runs tasks once before next frame takes its flags, so their invalidations join that frame. Tools reach it through required `ToolContext.scheduleFrame`; detached engine runs the task immediately because it produces no frames. Brush strokes append samples and decimate them incrementally per event, render accumulated stroke at most once per presented frame, render synchronously on commit.

## Lifecycle

Lifecycle states: `active`, `cooling`, `cool`, `disposed`. Losing final registry reference immediately banks a live floating selection, detaches input/render targets, cancels background PSD work, rasterization and the display's spatial adjustment jobs, releases old generation's reservations, starts a dirty-pixel flush. Successful, still-current flushes release every derived and group surface and each base cache that no read lease pins and no session holds, then trim history. Failed flushes keep dirty pixels and stay retryable; registry keeps the engine and retries after another grace period, disposing it only after a `cooled` result. Reacquisition increments lifecycle generation so late flush or grace-period work cannot clean up or dispose a live engine. Operation-owned reservations and pins survive these generation transitions until their owning operation settles.

Operations that write an open project's document elsewhere (close, export, duplicate) first cross its engine's paint barrier through open-project handle and Workbench's `LiveCanvasEngines` registry; close crosses it again after the push so pixels painted meanwhile are not lost. These barriers do not wait on an edit that holds dirty pixels (session, gesture or suspension): they fail fast and ask user to finish or cancel it, and if unsaved pixels cannot be persisted the project stays open with its engine state intact. Rename keeps its tolerant flush. Invocation waits for short-lived holds. The same registry lets Workbench's frame-size sync (`canvasDimsSync.ts`) record a frame resize that Generate's size asked for as one canvas step (`commitFrame`), so canvas undo restores frame and size together; without a live engine it is a `system` write. Disposal cancels outstanding work and releases every resource category: caches, decoded bitmaps, reservations, pins, outstanding snapshots.

Caller-owned `CanvasRasterSnapshot` objects are not reconstructible lifecycle caches. They stay usable through cooldown and keep counting against detached bytes until released. Final engine disposal force-releases them.

## Browser acceptance

Node and browser suites split by filename and config. `vitest.config.mts` excludes `*.browser.test.ts(x)`; `vitest.browser.config.mts` runs those files through `@vitest/browser-playwright` in headless Chromium. `test:browser` runs browser suite; `test:all` runs Node, then browser tests. CI installs Chromium with `pnpm exec playwright install chromium` before browser job.

Real-Canvas2D suite verifies transformed composition, clipping, alpha and blend modes, browser text metrics, PNG blob encoding, `createImageBitmap` decoding, pixel undo/redo, small PSD write/read round trip. React `StrictMode` harness verifies surface attachment, `ResizeObserver` sizing, detachment, registry cooldown/reacquisition, grace-period safety, project switching.

## Adding functionality

- New tool: implement tool interface under `tools/`, keep durable state in `CanvasProjectMutation`, expose only required tool capability methods.
- New derived effect: add stable effect kind/parameter key, construct through `DerivedSurfaceCache`, test warm hits, precise invalidation, stale source guards, culling, byte accounting.
- New layer operation: pure pixel/document math in core, orchestration in a controller; accept narrow ports, use project-bound mutations, reserve background allocations, return status unions for expected no-op/stale cases.
- New background raster workflow: capture document snapshot, plan required layers, reserve and pin before allocation, detach immutable surfaces, release every lease in `finally`, define whether edits after detachment are allowed.
- New application coordinator: place under `canvas-operations/`, acquire edit lease, capture through narrow document/export capabilities, own its session store and cancellation, publish through preview/layer capabilities.

Deterministic CI assertions use operation counters and byte totals. Wall-clock timing is informational only.

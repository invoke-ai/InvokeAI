# Identity session

Paths are relative to the webv2 `src/` directory.

App and Platform transport hand credential to Identity per [ARCHITECTURE.md](../../../ARCHITECTURE.md).

- Identity holds tab's bearer token in memory, bound to account lifetime it authenticates; once that lifetime ends no request can carry it. Each HTTP request captures token and lifetime together, and reports a returned `X-Refreshed-Token` (sliding renewal, or replacement after caller's own password change) and any 401 against that capture. Identity accepts a replacement only while capture's lifetime and token are still current, and a 401 only for current token, so a late response can neither renew nor expire a newer credential.
- Renewals replace token in place: no new lifetime, remount or cleanup. Media cookie re-issued at most every five minutes, since renewals do not extend it.
- Own password change runs as a credential rotation scoped to lifetime that queued it. Changes run one at a time; one still queued when its lifetime ends is rejected unsent, not dispatched with next account's credential. Until a rotation settles, other replacements are ignored, and a 401 for current token or another tab's renewal waits for its outcome: a delivered replacement supersedes them, a failed change lets them apply. Another tab's sign-out applies at once and discards replacement, because storage cannot tell a deliberate sign-out from any other and a deliberate one must end every tab.
- Rotation is announced in `localStorage` for its principal while in flight, each under its own key so concurrent changes from several tabs never overwrite one another. Withdrawn after replacement is stored, and when announcing tab leaves or ends its lifetime. Announcing also clears markers older than the wait and the single marker earlier builds wrote, whose announcements are not seen during a rolling upgrade. The announcement lets a tab whose token the change revokes hold the sign-out that 401 would cause (request itself still fails to its caller) until replacement is stored and adopted. Includes a tab whose own concurrent change the other change revoked. Session expires if every announcement of that principal is withdrawn without a replacement, or 30 seconds after latest one still announced if its tab never settles. A tab restoring or following a token rejected under an announced rotation waits the same way, then continues from whatever storage holds.
- Sign-in attempt leaves stored token alone until it succeeds.
- Socket authenticates every connect attempt with current token; reconnects after server closes a session whose token was replaced.
- `localStorage` persists token across reloads and carries other tabs' changes. Read when a session resolves and on reconciliation (`storage` events, back/forward-cache restores, returning to view), never per request. Another tab's renewal for the same principal (judged from token's `user_id` claim) is adopted in place; a removal signs this tab out; any other change ends current lifetime first, then resolves and activates new principal like a restored session, latest stored value winning. Rejected token signs tab out as expired; unreachable backend leaves it signed out with token stored and unobserved, so next reconciliation retries. Writes this tab made itself are not read back as changes; blocked storage leaves sign-in working for tab's lifetime.
